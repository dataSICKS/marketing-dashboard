# liny-api

AbemaTV「奇跡の歯ブラシ」のLINE（LINY）から、ダッシュボードの分母に使えるデータを
APIで直接取る。`out/` は gitignore（JSONと友だちIDが入るため）。

    ./run.sh      # 初回はトークンを聞く。collect.py → friends.py を続けて実行

- `collect.py` … タグフォルダ・タグ・**タグごとの保有者（友だちID＋ブロック状態）**
- `friends.py` … 友だちを全件1パス。**追加日・ブロック状態・各タグの付与日時**

氏名・uid・memo は保存しない。分析に使わない個人情報を持ち回らないため。

## APIの実挙動（2026-11-25 に実測して確認したこと）

- Base `https://api.lineml.jp/v2/api`／`Authorization: Bearer <token>`
- レート制限は**10リクエスト/秒**（超過は429・`Retry-After`なし）。月間上限はプラン依存で数値非公開。
  本スクリプトは0.17秒間隔＝約6リクエスト/秒。
- ページングは `cursor` ＋ `limit`。**`per_page` はリクエストに渡せない**（応答にだけ入る）。
  `limit` の上限はエンドポイントで違う … `/tags/{id}/friends` は **10000**、`/taiou-marks` は100、他は1000。
- **`/tag-folders` に `limit` を付けると422**（`このパラメータは許可されていません`）。
  ページングを持たないエンドポイントがある。`limit` を一律に付けてはいけない。
- `GET /friends` に**タグでの絞り込みは無い**。`include_tags[]`（最大100個）は
  「応答に含めるタグの指定」で、フィルタではない。タグ単位の一覧は `/tags/{id}/friends` だけ。
- `include_tags[]` を付けると各タグに **`attached_at`（付与日時）** が入る。これが期間を合わせる鍵。
- `GET /friends` のフィルタ … `is_blocked` / `display_status` / `created_at_from` / `created_at_to` /
  `custom_search_id` / `taiou_mark_id` / `name` / `friend_info_id`＋`friend_info_value` / `sort_by` / `sort_order`

## このAPIでは取れないもの

- **配信実績（配信数・開封数・クリック数・リッチメニューのタップ数）。エンドポイントが存在しない。**
  あるのは `GET /messages`（トーク履歴）だけで、配信の結果ではない。開封率・CTRは出せない。
- **ステップ配信そのもののエンドポイントも無い**（シナリオ・配信設定は取れない）。
  工程の到達人数は「各通に対応するタグ」からしか分からない。
- **タグごとの人数を返すエンドポイントも無い**（保有者を全件引いて数える）。
- **回答フォームの一覧も無い。** 使えるのは `GET /forms/{id}/answers` だけで、
  `{id}` は管理画面でフォームを開いたURLから拾うしかない。

## ⚠️ 分析の前提になる制約

- **ステップ配信のタグは 2026-03-23 〜 05-13 の約7週間しか付与されていない。**
  CVは2月〜11月あるので、**期間を揃えずに割ると率が倍以上ずれる**。
- **ステップ配信10〜19・SPOT・⑨ はタグ保有者0人。** 配信もCVも出ているのにタグが付いていない
  （シナリオにタグ付与ステップが無い）。新構成の到達人数は取れない。
- **「購入完了」タグは0人。** LINY側にCVが無いので、CVはECforce由来（`line_url_cv`・識別子単位）のまま。
  **友だち単位の真のCVRは作れない**（同一人物として突き合わせられない）。
- **「診断回答」0人／診断Q別も最大10人。** 診断は実質まだ動いていない（テストのみ）。
- ブロックの**日時は取れない**（`is_blocked` の現状だけ）。「追加後N日でブロック」は出せない。
